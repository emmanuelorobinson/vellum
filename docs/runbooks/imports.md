# Icons, pictures and imports (Prompt 42)

Four tools put outside content on the canvas as ordinary changes: one transaction, one undo step, attributed to the
agent (Invariant 1). Importers and libraries are pure ports (`ports/import.rs`); adapters hold the formats.

| Tool | What it does |
|---|---|
| `search_icons` | Find icons by words in Lucide, Feather, Phosphor and Material Symbols (outlined, rounded, sharp), or list the libraries |
| `insert_icon` | An icon as an editable `vector` layer: size, weight, fill, colour or colour variable. `metadata.icon` records where it came from |
| `fill_image` | A picture for an image layer or a shape's image fill: from `path` (repository file), `data` (base64) or `query` (stock). Stored in `<name>.assets/` by content hash |
| `import` | SVG (`text`, `data` or `path`), PNG/JPEG/WEBP, or a Figma copy (the clipboard HTML as `text`) as layers |

```sh
vellum tool search_icons --query "arrow right" --limit 5
vellum tool insert_icon --parent <frame id> --library lucide --name arrow-right --size 20 --weight 300
vellum tool import --parent <page id> --path design/logo.svg      # asks first (see below)
```

## What needs the person's permission

Canvas edits never do. Reading a repository file (`path`) and reaching the stock library (`query`) are outside the
canvas (Invariant 11): the tool asks the `PermissionBroker` through `vellum::permissions::Outside`
(`Brokered`). A `data` or `text` argument needs none: the agent already holds that content.

The daemon has no prompt to ask with until the Permission card exists (Prompt 50) and no settings loader for
`[permissions]` rules, so today `path` and `query` fail there with a message that says to pass `data` instead.
`Documents::set_outside` and `set_stock` are where a host that can ask plugs them in; the tests do so with a
real `Broker` over a scripted prompt.

## Icons

Six data files in `crates/adapters/icons/data/` (about 5.4 MB, generated by `scripts/icons-gen.mjs`; see its header
to update them) are compiled in and read on first use. Every icon is SVG path data in its set's own view box.

| Set | Icons | Weights | Fill |
|---|---|---|---|
| `lucide` | 1,891 | 100–700 (line width, weight ÷ 200 units; 400 is the set's own 2) | no |
| `feather` | 287 | the same | no |
| `phosphor` | 1,512 | 100, 300, 400, 700 (thin, light, regular, bold) | yes |
| `material-symbols-outlined`, `-rounded`, `-sharp` (also `material-symbols`, meaning outlined) | 700 each, the most used | 400 | yes |

The nearest weight the set has is used, and `insert_icon` says so in `notes`. A project's own SVG folder joins the
catalog through `Library::from_records` and `Catalog::with` (the composition root reads the files); Settings,
Assets (Prompt 54) is not built, so nothing configures a folder yet.

`icon` nodes (library, name, weight) exist in the file format, but nothing draws them yet, so `insert_icon` makes
`vector` layers, as ARCHITECTURE §3.6 says ("inserted as vector nodes").

## Importers

| Importer | Reads | Makes | Leaves out (noted) |
|---|---|---|---|
| `svg` | SVG 1.1 up to 4 MB, no scripts or external files | one clipped frame; `rect`, `ellipse`, `vector` (arcs and transforms baked in), `text` and `image` layers, groups flattened | gradients (first stop used), patterns, clip paths, masks, filters, linked images, CSS beyond simple selectors |
| `image` | PNG, JPEG, WEBP headers | one `image` layer at its size, at most 1600 px on its long side; the file is stored untouched | pixels are not decoded |
| `figma-clipboard` | the HTML Figma puts on the clipboard (`fig-kiwi`, deflate) | frames, groups, rects, ellipses, lines, vectors, text, with fills, strokes, corners, shadows and blurs | images (always noted), gradients, auto layout, component links, mixed text styles, blend modes; zstd pastes and FigJam are refused with a reason |

An importer returns node specs (no ids) and assets by reference (`"asset": "import:0"`); the tool stores the assets,
swaps in their hashes and commits one transaction. Every importer passes the shared contract suite, which includes
4 × 100 deterministic mutations of valid input to prove it never panics.

The Figma decoder is checked against the reference Kiwi implementation: `tests/fixtures/generate.mjs` writes the
fixtures with `kiwi-schema`. The schema in the fixtures is written from memory of Figma's names; **no live Figma
paste has been read**, so a real paste may carry a field or value this does not yet know. It goes by names in the
schema the paste carries, so unknown fields are ignored.

## Stock pictures

Provider choice and licence: ADR-009. The key is in the keychain as `stock.pixabay`; `PixabaySource::new(fetch,
secrets, clock)` is how a host builds it, with `vellum_model_http::HttpFetcher` for `fetch`. The fetcher is the only
HTTP client for this and refuses IP literals, `localhost`, private and link-local networks (checked on the addresses
it will connect to), redirects, non-https and oversized answers.
