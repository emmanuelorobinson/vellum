## Icons

Icons come from four open icon sets: Lucide, Feather, Phosphor and Material Symbols. An icon goes on the canvas as an
ordinary vector layer, so you can change its colour, size and stroke like any other shape.

From the command line, search by words, then insert:

```sh
vellum tool search_icons --query "arrow right" --limit 5 --json
vellum tool insert_icon --document design/app.vellum --parent <frame id> --library lucide --name arrow-right --size 20 --weight 300
```

Each set has its own weights. When the set does not have the weight you ask for, the nearest one is used, and the result
says so. The fill can be a colour, or a colour variable, so an icon follows the theme.

The layer keeps a record of where it came from, so you can tell which icon set an icon belongs to later.

## Pictures

`fill_image` puts a picture into an image layer or into a shape's image fill. It takes one of four sources:

- `path`: a file in your repo. Reading a file outside the canvas needs your permission.
- `data`: the picture's bytes, base64 encoded. No permission is needed, because the agent already holds the content.
- `query`: a search of the stock library. Reaching the library needs your permission, and a key.
- `prompt`: an image generated by the provider you configured. The provider's origin needs permission.

The picture is stored beside the document under its content hash, so the same picture is stored once however many layers
use it. Stock pictures keep their attribution and licence in the layer's metadata.

## Local image tools

Two tools work on a picture without any network access:

- **Remove background** keeps the picture's alpha and every other field of the layer. It needs a background-removal model
  that you install yourself, and {{brand}} does not download one.
- **Trace** turns flat artwork into editable vectors, and replaces the layer with them. The layer keeps its id, its place
  and its size. Tracing reports what it cannot keep, such as a fit or a crop.

Tracing accepts images up to one megapixel. Decoding accepts images up to 16 megapixels and 8192 pixels on a side.

## Generated images

Generated images need a provider you configure. The command line stores the provider's settings in a settings file next to
the daemon's state, and the provider's key in the keychain. The result is stored locally, and its metadata records the
provider and the model. The prompt and the provider's raw reply are not saved in the file.

The [image work](/docs/operations/runbooks/image-work) runbook lists the settings and the checks that were run. Live
requests to a provider were not verified in the repository.
